## The new game's visuals (crazygames-visuals, November 2026)

Everything the world around the track is made of is procedural and
built at run time in `game/src/env/`: no texture or model files ship.

| Asset | Where | Source | Licence |
|---|---|---|---|
| Sky dome, sun, stars, cloud streaks, horizon backdrop | `game/src/env/sky.js` | vertex colours from the preset, seeded noise | this repository |
| Terrain | `game/src/env/terrain.js` | a height grid from seeded value noise, vertex coloured by the theme | this repository |
| Props (trees, rocks, buildings, grandstands with crowds, towers, lamps, flags, tyre stacks, containers, cranes) | `game/src/env/props.js` | three.js primitives merged, vertex coloured | this repository |
| Asphalt and concrete grain, smoke, spark and rain sprites | `game/src/env/textures.js` | drawn on canvases at start | this repository |
| Sponsor atlas and the gantry banner | `game/src/env/textures.js` | made up names (`SPONSORS`) in the system font, drawn on a canvas; none is a real company | this repository |

No image or model was downloaded or generated by a model for this
work. The system font the sponsor boards use is whatever the device
has; nothing is fetched.

Why 0.184.0 and not the newest: 0.185 and 0.186 pass a texture view
`swizzle` string to WebGPU that Chromium 141 rejects as not of type
`GPUTextureComponentSwizzle`, and the renderer throws on the WebGPU path
rather than falling back (measured here in the headless Chromium the
parity test runs). Browsers between the arrival of WebGPU and that spec
change would get a blank game. 0.184.0 does not send it.
